FinBot — AI Financial Advisor

A production-grade, guarded chatbot that combines dual safety guardrails, retrieval-augmented generation, live market data tools, and real-time streaming — all built on NVIDIA's AI endpoints.

Python · Flask LangChain / LCEL NVIDIA AI Endpoints ChromaDB (Vector DB) RAG SSE Streaming yfinance · CoinGecko · Tavily
Introduction

What is FinBot?

FinBot is a guarded, retrieval-augmented financial chatbot. Every single message a user sends is checked, enriched, routed, and streamed back in real-time through a multi-stage pipeline before a single word of the answer is generated.

🛡️ Dual Safety Guardrails Core

Every message is checked by two NVIDIA safety models concurrently before any AI response is generated. Harmful messages never reach the LLM.

📚 RAG Knowledge Base Core

PDFs from BlackRock, Federal Reserve, and Vanguard are chunked, embedded, and stored in ChromaDB. Relevant passages are retrieved and injected into every prompt.

⚡ Live Tool Calls Core

The bot can call 5 real-time tools — stock data, crypto prices, web search, and calculators — when the question demands live data.

🌊 Server-Sent Events Core

Answers stream token-by-token to the browser via SSE, giving the user instant visual feedback. Reasoning tokens are shown live in a collapsible panel.

Architecture

System Architecture

FinBot is organized into 7 clean layers. Each layer has exactly one responsibility. Data flows downward from the browser to the LLM and back up via SSE.

1
Browser (Frontend)
User types a message in the React-like chat UI. JavaScript sends a POST to /chat with the message and full conversation history as JSON. Opens a streaming reader to receive SSE chunks.
templates/index.html · static/js/chat.js · static/css/style.css
2
Flask Route Handler (app.py)
The /chat route extracts the message and history from JSON, validates they exist, then calls chatbot.stream(). The response is wrapped in Flask's Response(stream_with_context(...)) with MIME type text/event-stream.
app.py
3
Dual Guardrail Check (guardrails.py)
The raw user message is simultaneously sent to two NVIDIA safety classifiers: Nemotron 3.5 Content Safety and Llama 3.1 Nemotron Guard 8B. If either blocks, a GuardrailError is raised — the LLM never sees the message. If "unauthorized advice" is detected, educational mode is enforced instead.
chatbot/guardrails.py
4
RAG Retrieval (rag.py)
The user's question is embedded using NVIDIA's llama-nemotron-embed-1b-v2 model. The top-4 most similar document chunks are retrieved from ChromaDB using cosine similarity. Only chunks with a score ≥ 0.3 are included. Source metadata (folder, filename, page) is tracked for UI attribution.
chatbot/rag.py
5
Prompt Assembly (prompts.py)
A LangChain ChatPromptTemplate assembles the final message list: [System Prompt] + [2 Few-Shot Examples] + [Chat History] + [RAG Context] + [Guardrail Note (if any)] + [User Message]. This fully formed prompt goes to the LLM.
chatbot/prompts.py
6
Tool Routing & Execution (chain.py + tools.py)
A dedicated router model (fast, low reasoning budget) inspects the prompt with all 5 tools bound to it. It decides whether to call a tool. If yes, the tool runs (Tavily search, yfinance, CoinGecko, or a calculator). Results are appended as a system message. Then the main model generates the final answer.
chatbot/chain.py · chatbot/tools.py
7
SSE Response Streaming (app.py → browser)
The answer is streamed token-by-token as data: {...}\n\n SSE events. Separate event types carry: status updates, tool call notifications, reasoning tokens (chain-of-thought), content tokens, and RAG source attribution. The browser renders each chunk incrementally using marked.js.
app.py · static/js/chat.js

Layer 2

Flask App — app.py

app.py is the web server. It exposes 4 routes, handles startup errors gracefully, and wraps the chatbot pipeline in a streaming HTTP response.

RouteMethodWhat it does
GET / GET Renders index.html via Jinja2. Injects init_error (any startup error) and model_label (active AI model name) into the template.
GET /health GET Returns {"status": "ok"} or {"status": "error", "error": "..."}. Used for health checks / monitoring.
GET /api/market GET Fetches live stock data (yfinance) and crypto data (CoinGecko API). Returns two arrays: pulse (5 major indices) and tape (12 symbols for the scrolling ticker). Called by the browser every 5 minutes.
POST /chat POST The main chat endpoint. Reads message and history from the JSON body. Calls chatbot.stream() and wraps the generator in Flask's SSE response. On GuardrailError, yields a blocked event. On any other exception, yields an error event.
⚠️

Graceful startup: If FinancialChatbot() fails (e.g., missing API key), the app still starts. chatbot is set to None and _init_error stores the message. The /chat route returns HTTP 503 if the chatbot is not initialized. The / route shows a red banner in the UI.

python · app.py — SSE generator
def generate():
    try:
        for chunk in chatbot.stream(user_message, chat_history):
            # Each chunk is a dict like {"content":"..."} or {"status":"..."}
            yield f"data: {json.dumps(chunk)}\n\n"
    except GuardrailError as exc:
        # Blocked message — send blocked event, then stop
        yield f"data: {json.dumps({'error': exc.message, 'blocked': True})}\n\n"
    except Exception as exc:
        yield f"data: {json.dumps({'error': str(exc)})}\n\n"
    yield "data: [DONE]\n\n"   # Signal end of stream

return Response(
    stream_with_context(generate()),
    mimetype="text/event-stream",
    headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
)
Layer 3

Guardrails — guardrails.py

The first gate every user message passes through. Two safety models run in parallel before any financial reasoning begins. This is the project's most critical safety system.

Guard 1: Nemotron 3.5 Content Safety Multimodal

Model: nvidia/nemotron-3.5-content-safety

Sends the message with a special chat_template_kwargs requesting category classification with "thinking" enabled. The response is a plain text string like:

user safety: safe
— or —
user safety: unsafe
safety categories: violence, hate speech

The code parses lines to extract the safety verdict and categories. The category unauthorized advice is in the allowed list — it does not block but triggers educational mode.

Guard 2: Llama 3.1 Nemotron Guard 8B 23-Category

Model: nvidia/llama-3.1-nemotron-safety-guard-8b-v3

Returns a JSON object with normalized safety labels:

{
  "User Safety": "unsafe",
  "Safety Categories": "Violence"
}

Keys are normalized to lowercase before checking. Has fallback parsing if the response is not valid JSON (searches raw text for "unsafe"). Covers 23 harm categories including violence, self-harm, sexual content, and more.

🔀

Parallel execution via LCEL: Both guards run simultaneously using LangChain's RunnableParallel. This means the total guardrail latency equals the slower of the two models, not the sum. This is a key performance optimization.

python · guardrails.py — parallel chain
# Both guards run on the SAME input string at the same time
guardrail_chain = RunnableParallel(
    nemotron_safety=RunnableLambda(_nemotron_safety_call),   # Guard 1
    nemotron_guard=RunnableLambda(_nemotron_guard_call),    # Guard 2
)
# Result: {"nemotron_safety": {...}, "nemotron_guard": {...}}

Decision Logic in chain.py

1
Both guards say safe
Pipeline continues normally. guardrail_note is an empty string.
Continue
2
Either guard flags "unauthorized advice"
The message is not blocked. Instead, NON_ADVISORY_NOTE from prompts.py is injected into the prompt. The LLM is forced into educational-only mode: no specific tickers, no "you should buy X", no personalized plans.
Educational Mode
3
Either guard flags truly harmful content
A GuardrailError exception is raised immediately. The exception propagates up to app.py's generate() function which sends a {"blocked": true} SSE event. The browser shows a "Blocked by Safety Guardrails" panel. The LLM is never called.
Hard Block
🔓

"Fail open" safety: If a guard fails due to an API error (network timeout, wrong key, etc.), it returns {"safe": True} — it fails open. This is a deliberate design choice to prevent API errors from blocking legitimate users. The error is logged to the console but the pipeline continues.

Layer 4

Retrieval-Augmented Generation — rag.py + ingest.py

RAG gives the chatbot authoritative, factual knowledge from real financial documents, instead of relying solely on the LLM's training data which may be outdated or hallucinated.

Part A — ingest.py (run once, offline)

1
Load PDFs
Walks knowledge_base/**/*.pdf recursively. Uses pypdf.PdfReader to extract text page-by-page. Tags each page with metadata: source_file, source_folder, and page number.
2
Split into Chunks
RecursiveCharacterTextSplitter splits each page into overlapping chunks of 1000 characters with a 200 character overlap. The overlap ensures that context at chunk boundaries isn't lost when retrieving.
3
Embed & Store
Each chunk is converted to a vector embedding using NVIDIA's llama-nemotron-embed-1b-v2 model via the NVIDIA AI Endpoints API. Vectors are stored in ChromaDB under the collection finbot_knowledge using cosine similarity as the distance metric. ChromaDB persists to chroma_db/.

Part B — rag.py (called every request)

🗄️
Singleton DB Pattern
The ChromaDB connection is created once and reused for all requests
›

The _db global variable starts as None. On the first call to _get_db(), it loads the ChromaDB from disk, creates the embedding model, and stores the connection. All subsequent calls return the cached connection. This prevents expensive re-initialization on every message.

python · rag.py — singleton pattern
_db = None   # module-level singleton

def _get_db() -> Chroma:
    global _db
    if _db is not None:
        return _db     # already initialized — return cached
    # First call: build the DB + embedding model
    embeddings = NVIDIAEmbeddings(model="nvidia/llama-nemotron-embed-1b-v2", ...)
    _db = Chroma(persist_directory=CHROMA_PATH, ...)
    return _db
🔍
retrieve() Function — Query → Context + Sources
Top-4 cosine similarity search with score threshold filtering
›
  • Embeds the user's query using the same llama-nemotron-embed-1b-v2 model used during ingestion. Using the same model for both steps is critical for accurate similarity scores.
  • Calls similarity_search_with_relevance_scores(query, k=4) — returns the 4 closest chunks with cosine similarity scores in [0, 1].
  • Applies a score threshold of 0.3: chunks scoring below 0.3 are considered irrelevant and discarded. This prevents injecting noise into the prompt when the knowledge base has nothing relevant.
  • For each passing chunk, formats it as: [Source N: folder/filename]\n{text}.
  • Deduplicates sources by folder/file key — the same file won't appear twice in the source attribution panel even if two chunks from it are retrieved.
  • Returns a tuple: (context_string, sources_list). The context string goes into the prompt. The sources list goes to the frontend for RAG attribution badges.
📌

Knowledge Base Contents: BlackRock's BII Mid-Year Outlook 2026 · Federal Reserve Beige Book June 2026 · Vanguard Retirement Income · Vanguard Global Equity · Vanguard Inflation Hedging · Vanguard Asset Location. Total: 6 documents across 3 organizations.

Layer 5

Prompts — prompts.py

prompts.py is the "instruction manual" given to the LLM. It defines the bot's identity, capabilities, decision rules, output format, and the safety override used by the guardrail system.

📜
SYSTEM_PROMPT — FinBot's Identity & Rules
Always the first message in the context window
›
  • Identity: "You are FinBot, an AI financial advisor. Provide clear, accurate, structured answers with specific numbers and actionable takeaways."
  • Tool table: A Markdown table mapping each tool to the trigger condition — the LLM uses this to decide when to call which tool.
  • Tool call rules: Explicit "when to call" instructions: stock price → get_stock_data, news → search_financial_web, crypto → get_crypto_price.
  • Disclaimer: Ends every investment recommendation with: "⚠️ Educational only — not personalized financial advice."
💡
Few-Shot Examples — Teaching by Demonstration
2 high-quality example Q&A pairs shown before every chat
›

Two complete example conversations are injected before the actual chat history. This teaches the model by example what a great FinBot answer looks like — structured tables, specific numbers, action plans, and the disclaimer. The examples cover:

Example 1

"How do I build a diversified portfolio with $10,000?" — Full table with allocations, ETF names, 20-year projection, step-by-step action plan.

Example 2

"Roth IRA vs Traditional IRA?" — Feature comparison table, decision framework, the math on a 30-year horizon, next steps.

These are implemented using FewShotChatMessagePromptTemplate — a LangChain helper that serializes them as proper HumanMessage / AIMessage pairs in the context window.

🔒
NON_ADVISORY_NOTE — Guardrail Override Prompt
Injected when the guardrail detects "unauthorized advice"
›
python · prompts.py
NON_ADVISORY_NOTE = (
    "⚠️ GUARDRAIL ACTIVE — EDUCATIONAL MODE ENFORCED: "
    "The user's message was flagged as a request for personalized financial advice. "
    "You MUST respond with financial insights and education ONLY. "
    "Do NOT provide: specific ticker symbols to buy, exact dollar amounts to allocate, "
    "personalized step-by-step investment plans, or direct 'you should do X' statements. "
    "Instead: explain the relevant financial principles, discuss options objectively, "
    "highlight key considerations and trade-offs, and cite knowledge-base sources. "
    "End your response with the standard non-advisory disclaimer."
)

This is injected as a SystemMessage at the end of the prompt chain, giving it highest-priority instruction weight. It's what allows FinBot to still be helpful on investment questions without crossing into unregulated financial advice territory.

Layer 6

Tools — tools.py

Five LangChain @tool-decorated functions that the LLM can call when it needs real-time data or calculations. Each tool has a name, a docstring (used by the LLM to decide when to call it), and typed parameters.

🔍 search_financial_web Tavily API

Trigger: Recent news, earnings, analyst upgrades, market events — any question needing up-to-date web data.

How it works: Calls TavilyClient.search() with search_depth="advanced", topic="finance", up to 5 results with 3 content chunks each. Returns formatted Markdown with title, URL, score, and content snippet per result.

TAVILY_API_KEY finance topic filter 5 results max
📈 get_stock_data yfinance

Trigger: Current price, P/E, market cap for any ticker symbol (AAPL, TSLA, SPY, BRK-B…).

How it works: Calls yf.Ticker(ticker).info to retrieve a comprehensive dict of fundamentals. Extracts and formats: current price, market cap, P/E (TTM), EPS, 52-week range, dividend yield, revenue, analyst target, recommendation key.

No API key needed Real-time 9 data fields
🪙 get_crypto_price CoinGecko

Trigger: Live cryptocurrency prices — accepts CoinGecko IDs (bitcoin, ethereum, solana…).

How it works: Hits the free CoinGecko /simple/price endpoint with USD as the base currency, requesting price, market cap, 24h change, and volume. No API key required. Uses directional arrow (▲/▼) for the change.

No API key needed CoinGecko IDs 4 data fields
📊 calculate_compound_growth Pure Python

Trigger: Investment projections, retirement savings, emergency fund goals — "how much will X grow to in Y years at Z% return?"

How it works: Implements the standard compound interest formula with optional monthly contributions:
FV = P(1+r)ⁿ + C × ((1+r)ⁿ - 1) / r
where r = monthly rate, n = months. Returns total invested, total growth, and final value.

4 parameters monthly compounding no API
🏦 calculate_loan_payment Pure Python

Trigger: Mortgage affordability, car loans, student debt — "what will my monthly payment be?"

How it works: Standard amortization formula:
M = P × r(1+r)ⁿ / ((1+r)ⁿ - 1)
Returns monthly payment, total paid over the life of the loan, and total interest cost. Handles the zero-rate edge case (interest-free loans).

3 parameters full amortization no API
🔗

How tools are bound to the LLM: FINBOT_TOOLS = [tool1, tool2, ...] is a list of decorated functions. In chain.py, the router model is created with router_model.bind_tools(FINBOT_TOOLS). LangChain serializes each tool's name and docstring into the LLM's function-calling schema. When the LLM wants to call a tool, it emits a special tool_calls attribute on the response, which chain.py detects and dispatches.

Layer 7

Chain / Brain — chain.py

FinancialChatbot is the orchestrator class. Its stream() method is a Python generator that coordinates all other layers and yields live status events, tool events, reasoning tokens, and content tokens.

🏗️
__init__() — Model Configuration & Setup
Controlled by the FINBOT_MODEL environment variable
›
FINBOT_MODELModelThinkingSpeedReasoning Budgets
llama meta/llama-3.3-70b-instruct ❌ No Fastest N/A (single instance)
super nvidia/nemotron-3-super-120b-a12b ❌ No Fast N/A (single instance)
ultra nvidia/nemotron-3-ultra-550b-a55b ✅ Yes Slowest fast=1024, balanced=4096, deep=16384, router=512

For thinking models (Ultra), four separate model instances are created with different reasoning_budget values. The answer model always uses "balanced" (4096 tokens). The router gets a tiny budget (512) to stay fast. Non-thinking models (Llama/Super) reuse a single instance for all levels.

All models are also .bind_tools(FINBOT_TOOLS)-ed to create tool-aware variants stored in self._agent_models and self._router_agent.

🔀
Tool Routing System — The "Router Model" Pattern
A small, fast dedicated model decides if tools are needed
›

Instead of making the expensive answer model (Nemotron Ultra 550B) decide tool routing, a dedicated router model with minimal reasoning budget (512 tokens) first reads the entire prompt with tools bound to it and decides whether to call any tool. If yes, the tools run. Then the actual answer model generates the final response with tool results injected.

⚡

Why this matters: The router model can make its routing decision in seconds. The 550B answer model focuses only on generating a high-quality response — it doesn't waste reasoning budget on whether to call a tool.

Routing hint: A SystemMessage is appended before routing that explicitly constrains when to call tools. Critically, if RAG context was already found, the hint says "The knowledge base already has relevant information — do NOT call search_financial_web." This prevents redundant web searches.

🧹
Citation Cleaning — _clean()
Strips Nemotron citation markers before streaming to the UI
›

Nemotron models inject citation markers like 【{"id":0,"cursor":0,"loc":0}】 when referencing tool or knowledge base content. These are JSON-encoded Unicode bracket characters (U+3010 and U+3011). The _CITATION_RE regex strips these before each content chunk is yielded to the SSE stream.

python · chain.py
_CITATION_RE = re.compile(r'\u3010[^\u3011]*\u3011')

def _clean(text: str) -> str:
    return _CITATION_RE.sub('', text)  # remove 【...】 markers

The stream() Generator — Step by Step

①
yield {"status": "🛡️ Checking safety…"}
Immediately yields a status event so the UI shows "Checking safety…" while the guard models run. Then calls _check_guardrails() which invokes the parallel guardrail chain. Raises GuardrailError if blocked.
②
yield {"status": "📚 Searching knowledge base…"}
Converts raw history dicts to LangChain message objects via _format_history(). Then calls _add_rag_context() to retrieve relevant document chunks from ChromaDB. Yields {"sources": [...]} immediately so the UI knows which sources were used even before the answer starts.
③
Prompt Assembly
Calls PROMPT_TEMPLATE.invoke({...}) to build the full message list: system prompt + few-shot examples + history + RAG context + optional NON_ADVISORY_NOTE + user message. Then appends the routing hint SystemMessage.
④
yield {"status": "Routing…"} → Router Model Run
Streams the router model to get the full ai_msg. Extracts ai_msg.tool_calls. If the list is non-empty, tools were requested. Logs the tool names and time taken.
⑤
Tool Execution (if requested)
For each tool call: yields {"tool_call": name} (shows spinner badge in UI), looks up the function in self._tool_map, calls tool_fn.invoke(args), appends the result as a SystemMessage to the message list. After all tools: yields {"tool_done": True} (stops spinners).
⑥
Answer Generation — Streaming Chunks
The balanced answer model (without tools bound — it only generates text) streams the final response. For each chunk, extracts reasoning_content (chain-of-thought) and content (actual answer) separately. Each is passed through _clean() and yielded as {"reasoning": "..."} or {"content": "..."} events.
Deep Dive

Full Request Lifecycle

A complete walkthrough of exactly what happens from the moment a user presses Enter to when the last character of the response renders in the browser.

1
User presses Enter
sendMessage() in chat.js fires. The user bubble is immediately appended to the DOM. Input is cleared and disabled. The message is pushed to chatHistory[]. A bot bubble placeholder with a typing indicator (three animated dots) is created.
2
POST /chat
Fetch API sends {"message": "...", "history": [...]} to Flask. The history array contains all previous turns except the current one (to avoid including the "empty" bot reply that hasn't been answered yet).
3
Flask validates & delegates
app.py extracts and validates the message. Returns HTTP 400 if empty, HTTP 503 if chatbot not initialized. Otherwise creates the SSE generator and returns a streaming Response.
4
Browser receives: {"status": "🛡️ Checking safety…"}
The status pill in the header changes to amber + "Checking safety…". Meanwhile, both NVIDIA safety models are running concurrently on the server. The browser is already reading the stream; it just has nothing to show yet.
5
Browser receives: {"status": "📚 Searching knowledge base…"}
Safety passed. The user's query is now being embedded and searched against ChromaDB. Status updates in the header pill.
6
Browser receives: {"sources": [...]}
The list of RAG sources that were retrieved is sent immediately — before the answer starts. chat.js stores this as ragSources and will display it as attribution badges after the answer finishes.
7
Browser receives: {"status": "Routing…"}
The router model is now running. The prompt with all context + routing hint is being processed. The status pill shows "Routing…".
8a
[If tool needed] Browser receives: {"tool_call": "get_stock_data"}
showToolCall() inserts a spinning badge "Using get_stock_data ⟳" above the answer bubble. Status changes to "Using get_stock_data…". The actual yfinance call is running on the server.
8b
[If tool needed] Browser receives: {"tool_done": true}
All tool spinners are removed. Tool results have been injected into the message list as a SystemMessage on the server. The answer model begins generating.
9
[Ultra only] Browser receives: {"reasoning": "…"}
For the Nemotron Ultra model, chain-of-thought tokens arrive before content. updateReasoning() appends each chunk to the think panel (which auto-opens like DeepSeek). Status is still "Thinking…". Scroll is throttled to one rAF per frame.
10
Browser receives: {"content": "## BlackRock…"} (first content chunk)
Status pill turns blue and shows "Responding…". The typing indicator dots are replaced by the first rendered Markdown. updateContent() uses rAF batching — multiple chunks per frame are coalesced into one DOM write. A blinking cursor is appended at the end.
11
Content chunks stream in…
Hundreds of partial tokens arrive as individual SSE events. Each one is appended to fullContent. The entire accumulated Markdown is re-parsed and rendered on every animation frame (not every chunk) to avoid layout thrashing.
12
Server sends: data: [DONE]
The SSE stream ends. finalise() is called: cancels any pending rAF, does a final Markdown render, runs highlight.js on all code blocks, adds "Copy" buttons to code blocks, appends RAG source badges, adds the "Copy response" action button. chatHistory is updated with the full assistant response.
13
UI returns to ready state
Status pill returns to green "FinBot Ready". Input is re-enabled. streaming flag is set to false. The send button re-enables when the user starts typing.

Server-Sent Events (SSE) — The Communication Protocol

FinBot uses SSE instead of WebSockets. SSE is one-directional (server → browser), perfectly suited for AI token streaming, and requires no special server setup beyond Content-Type: text/event-stream.

Event Types sent by the server

Payload ShapeMeaningUI Action
{"status": "…"}Pipeline stage updateUpdate header status pill
{"sources": [...]}RAG results readyStore for post-stream display
{"tool_call": "name"}Tool execution startedShow spinning tool badge
{"tool_done": true}All tools finishedRemove spinners
{"reasoning": "…"}CoT reasoning tokenAppend to think panel
{"content": "…"}Answer tokenStream Markdown render
{"error": "…"}Non-fatal errorShow error toast
{"error":"…","blocked":true}Guardrail blockShow blocked panel
[DONE]Stream endedCall finalise(), reset UI

SSE Wire Format

HTTP response body (text/event-stream)
data: {"status": "🛡️ Checking safety…"}

data: {"status": "📚 Searching knowledge base…"}

data: {"sources": [{"folder":"BlackRock","file":"outlook.pdf","page":3}]}

data: {"status": "Routing…"}

data: {"tool_call": "get_stock_data"}

data: {"tool_done": true}

data: {"status": "📝 Composing answer…"}

data: {"reasoning": "The user is asking about AAPL stock. I should…"}

data: {"content": "## Apple Inc. (AAPL)\n\n"}

data: {"content": "**Current Price:** $217.96\n"}

data: {"content": "Based on the fundamentals…"}

data: [DONE]
🔧

Flask headers: Cache-Control: no-cache prevents proxy/CDN buffering. X-Accel-Buffering: no disables nginx response buffering. Both are required for real-time streaming to work in production environments. stream_with_context() ensures Flask's request context is available inside the generator even in threaded mode.

AI Models Used

FinBot orchestrates up to 6 different AI models in a single request pipeline — 2 safety classifiers running in parallel, 1 embedding model, 1 router model, and 1 answer model. All hosted on NVIDIA AI Endpoints.

Model ID Role Called In Notes
nvidia/nemotron-3.5-content-safety Guard 1 guardrails.py Multimodal/multilingual safety. Returns text verdict with category breakdown. Runs with enable_thinking: True.
nvidia/llama-3.1-nemotron-safety-guard-8b-v3 Guard 2 guardrails.py 23-category JSON classifier. 8B parameter model — fast. Runs in parallel with Guard 1.
nvidia/llama-nemotron-embed-1b-v2 Embeddings rag.py + ingest.py Converts text to dense vectors. Must be the same model for both indexing and querying. 1B params = fast + accurate.
meta/llama-3.3-70b-instruct Answer (llama) chain.py Default model. No chain-of-thought. Fastest option. Best tool-use compliance. 120s timeout.
nvidia/nemotron-3-super-120b-a12b Answer (super) chain.py 120B MoE model. No thinking. Good balance of speed and quality. 180s timeout.
nvidia/nemotron-3-ultra-550b-a55b Answer (ultra) chain.py 550B MoE model. Full chain-of-thought reasoning. Creates 4 instances (3 reasoning budgets + 1 router). 600s timeout. Emits reasoning_content separate from answer content.
💡

Why use a separate router model? The answer model (especially Ultra 550B) is expensive and slow to start. Making it decide whether to call a tool wastes valuable reasoning budget. A tiny 512-token-budget router model can make the routing decision in seconds, then the powerful model focuses entirely on generating a quality financial answer.

Reference

Technology Stack

Every library and external API used in the project, with its exact role.

🌐 Flask Web

Python web framework. Handles HTTP routing, Jinja2 templating, and SSE response streaming. Runs in threaded mode for concurrent SSE connections.

🔗 LangChain AI Orchestration

Provides ChatPromptTemplate, FewShotChatMessagePromptTemplate, MessagesPlaceholder, RunnableParallel, RunnableLambda, @tool decorator, and message type classes.

🤖 langchain-nvidia-ai-endpoints LLM Client

Official NVIDIA wrapper for ChatNVIDIA and NVIDIAEmbeddings. Supports streaming, tool-calling, reasoning_budget, and chat_template_kwargs for enabling thinking mode.

🗄️ ChromaDB Vector DB

Embedded vector database that persists to disk. Stores document embeddings in a SQLite file. Provides cosine similarity search with relevance score filtering. No server required.

📄 pypdf PDF Parsing

Extracts text from PDF files page by page during the ingest.py pipeline. Used only at ingestion time, not at query time.

✂️ langchain-text-splitters Chunking

RecursiveCharacterTextSplitter splits documents into 1000-char chunks with 200-char overlap. The recursive approach tries to split on paragraphs first, then sentences, then words.

📊 yfinance Market Data

Unofficial Yahoo Finance Python wrapper. Used in two places: the get_stock_data tool (per-ticker fundamentals) and the /api/market endpoint (batch sidebar/tape data). No API key required.

🔎 Tavily Web Search

AI-optimized web search API. Used in search_financial_web tool with search_depth="advanced" and topic="finance" filter for relevant, recent financial news. Requires TAVILY_API_KEY.

🪙 CoinGecko API Crypto Data

Free, no-auth cryptocurrency price API. Used in both the get_crypto_price tool (per-coin lookup) and the /api/market endpoint (BTC/ETH sidebar data). Accessed via raw requests.get().

⚙️ python-dotenv Config

Loads .env file variables (NVIDIA_API_KEY, TAVILY_API_KEY, FINBOT_MODEL) into environment variables at startup. Called in both app.py and ingest.py.

📝 marked.js Frontend

Markdown → HTML renderer running in the browser. Called on every animation frame during streaming to render partial Markdown responses. Configured with GitHub-Flavored Markdown and highlight.js integration.

🎨 highlight.js Frontend

Syntax highlighter for code blocks. Applied in finalise() (not during streaming — to avoid constant re-highlighting). Uses the github-dark theme.
